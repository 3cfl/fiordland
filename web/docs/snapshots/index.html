Snapshots and rollback

Undo a bad update with Btrfs snapshots.

What is saved

Fiordland uses Btrfs and snapper. A snapshot is a frozen copy of the system, not your home folder. Snapshots are taken before and after every package change, and every hour (5 hourly, 7 daily, 2 weekly and 1 monthly are kept).

snapper -c root list

Undo an update while the system works

Find the snapshot pair for the bad update in the list (the pre and post numbers), then:

sudo snapper -c root undochange PRE..POST

Restart afterwards.

Roll back when the system does not boot

  1. Pick a snapshot

    Restart, open Fiordland snapshots in the boot menu and pick one from before the problem. Each entry shows its date and what caused it.

  2. Check it works

    The system starts from the snapshot. Changes made now are kept in memory and lost at the next restart.

  3. Make it permanent

    sudo fiordland-rollback

    Restart, and Fiordland starts from the restored system. Your home folder is not touched.

  4. Free the space

    sudo fiordland-rollback --clean

    Deletes the old system once everything works.

Each snapshot carries its own kernel, so this also undoes a bad kernel update. To restore by number without booting it first, use fiordland-rollback --list and then sudo fiordland-rollback N.

Installs from before 23 November 2026

Older installs use systemd-boot, so the snapshot menu is not there. Boot the USB stick, open a terminal, and:

lsblk -f
sudo mount -o subvolid=5 /dev/nvme0n1p2 /mnt
sudo ls /mnt/@snapshots
sudo mv /mnt/@ /mnt/@broken
sudo btrfs subvolume snapshot /mnt/@snapshots/N/snapshot /mnt/@
sudo umount /mnt

Use the btrfs partition from lsblk -f, and info.xml in each snapshot folder for its date. If a kernel update caused the problem, run sudo pacman -S linux-cachyos linux after restarting.
